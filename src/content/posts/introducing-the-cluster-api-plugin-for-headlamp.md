## Architecture and Motivation

Operating Cluster API (CAPI) via raw `kubectl` requires operators to manually traverse complex ownership hierarchies and decode Secrets to debug provisioning failures. The Headlamp Cluster API plugin abstracts this by mapping the management cluster's state into a visual, topology-aware interface.

By natively understanding CAPI resource relationships, the plugin accelerates root-cause analysis for stalled cluster lifecycles, surfacing degraded conditions and infrastructure API failures without requiring manual command-line tracing.

## Core Capabilities

### Structural Visualization

CAPI heavily utilizes owner references to link high-level abstractions to granular infrastructure resources. The plugin's **Map View** automatically resolves these references, rendering the topology from the `Cluster` down to the bootstrap configuration:

```text
Cluster
 │
 ├── Control Plane (KubeadmControlPlane)
 │    └── Machine (Infrastructure: AWSMachine, etc.)
 │
 └── Worker Groups (MachineDeployments / MachinePools)
      └── MachineSet
           └── Machine
                └── Bootstrap Config (KubeadmConfig)
```

### Operational Workflows

*   **Secret-less Bootstrap Inspection:** Extracting `join` configurations or `kubelet` arguments typically requires retrieving and base64-decoding underlying Secrets generated by `KubeadmConfig`. The plugin parses these objects natively, displaying inline files, volumes, and initialization parameters directly in the UI.
*   **Topology-Aware Scaling:** Operators can adjust replica counts on `MachineDeployments` and `MachineSets` directly from the dashboard. For clusters utilizing `ClusterClass` (Topology-managed clusters), the plugin enforces architectural constraints by redirecting scaling operations to the top-level `Cluster` object, preventing reconciliation loops and state drift.
*   **Multi-Version Support:** The plugin seamlessly handles API translations, supporting both `v1beta1` and `v1beta2` CAPI objects in the management cluster.

### Integrated Observability

When combined with the Headlamp Prometheus plugin, live metrics are injected directly into CAPI resource views (`Clusters`, `MachineDeployments`, `Machines`). This co-locates declarative state (e.g., `Phase: Provisioning`, Provider IDs) with telemetry, allowing operators to correlate infrastructure orchestration events with resource utilization metrics without context switching.

## Trade-offs and Operational Nuance

*   **Declarative Drift:** While the plugin allows for UI-driven scaling and management, leveraging these features in production can introduce drift if the management cluster is driven by a GitOps reconciler (e.g., Flux, ArgoCD). UI mutations should be reserved for break-glass remediation or ephemeral development environments.
*   **Condition Aggregation:** CAPI failures often manifest deep in the hierarchy (e.g., an `AWSMachine` failing to acquire an IP). The dashboard aggregates active condition issues at the top level, but operators must still understand the underlying provider's failure domains; the UI highlights the failure but cannot bypass cloud provider limits or network misconfigurations.
