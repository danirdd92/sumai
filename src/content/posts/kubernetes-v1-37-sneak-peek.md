# Kubernetes v1.37: Architectural & Operational Changes

## Breaking Changes & Removals

### SELinux Volume Relabeling (GA)
`SELinuxMount` is enabled by default. Volumes mount with `-o context=<label>` instead of recursively relabeling every file. This drastically improves mount performance but changes how contexts are applied. This behavior requires the storage CSI driver to opt in via `.spec.seLinuxMount: true` in the `CSIDriver` object.

**Failure Mode:** A single mount can hold only one SELinux context. Pods with differing SELinux labels sharing the same volume on a single node will fail to start.

**Mitigation:** To force legacy recursive relabeling for a specific workload, define it in the Pod spec:
```yaml
spec:
  securityContext:
    seLinuxChangePolicy: Recursive
```

### Kubelet: Static Pod API Restrictions
Static Pods bypass the API server and should not read API resources directly. A patched bug previously allowed them to reference Secrets or ConfigMaps via `configMapRef` or `secretRef`. 

**Impact:** These references are now strictly prohibited. The `PreventStaticPodAPIReferences` feature gate—which previously allowed bypassing this restriction—has been removed. Static pods containing these references will fail on startup.

### Kube-Proxy: IPVS Mode Deprecated
The `ipvs` mode in `kube-proxy` is deprecated (KEP-5495) because the kernel IPVS API cannot fully implement Kubernetes Services, forcing a fallback to `iptables` under the hood. 

**Timeline:**
- **v1.40:** Disabled by default.
- **v1.43:** Completely removed.

**Audit Current State:**
```bash
kubectl -n kube-system get configmap kube-proxy -o jsonpath='{.data.config\.conf}' | grep 'mode:'
```

### Kubectl: `run -f` Deprecation
The `--filename` / `-f` flag for `kubectl run` is deprecated. Pods generated by this command are built strictly from CLI arguments (like `NAME` and `--image`), rendering file references obsolete.

**Refactoring:**
```bash
# Deprecated
kubectl run my-pod -f pod.yaml

# Correct (Declarative)
kubectl apply -f pod.yaml

# Correct (Imperative)
kubectl run my-pod --image=nginx
```

## Ongoing System Migrations

### Cgroup v1 Phased Out
Kubernetes mandates `cgroup v2` for advanced resource management (e.g., In-Place Pod Resizing, Tiered Memory Protection). Nodes running the legacy `cgroup v1` will cause the kubelet to fail initialization.

**Short-Term Workaround (Node Level):**
```yaml
apiVersion: kubelet.config.k8s.io/v1beta1
kind: KubeletConfiguration
failCgroupV1: false # Temporary override; migrate to v2 immediately
```

## Featured Enhancements

### Kubelet in UserNS (Beta)
Rootless Mode allows node components (like the `kubelet`) to run within a Linux user namespace as an unprivileged host user while retaining root privileges strictly within the namespace. This reduces the blast radius of container escape or node component vulnerabilities by eliminating the need for host-level root access.

### Volume Health Monitor (Alpha)
Historically, storage failures surfaced only as hung I/O or failed mounts, requiring manual cross-referencing with external vendor dashboards. This update introduces native, machine-readable storage health reporting via new CSI RPCs.

**Architecture:**
- **Controller-Side:** Polled via `ControllerListVolumeHealth` and `ControllerGetVolumeHealth`. Emits state to `PersistentVolumeClaim.status.healthStatus`.
- **Node-Side:** Polled via `NodeGetVolumeHealth`. Emits state to `Pod.status.volumeHealth`.
- **Driver Health:** Polled via `NodeGetStorageHealth`. Emits state to `CSINode.status.storageHealth`.

**Vocabulary:** Statuses are standardized (e.g., `Inaccessible`, `Degraded`), supplemented by extensible `reason` and `message` fields from the underlying CSI driver.

### Metrics API (GA)
The `metrics.k8s.io` API graduates to Stable (v1) after nine years. It provides standard CPU and memory telemetry for pods/nodes, powering the Horizontal Pod Autoscaler (HPA) and `kubectl top`. Both `v1` and `v1beta1` remain usable to prevent breaking automated pipelines.
